# Requirements

## Essential Need
用户要求修复第4步长流程回答遗漏并优化。延续已确认约束：单次最终生成、16GB/9B、不增加在线核验或模型重试；设计与独立并行评审先于编码，真实多轮与新留出确认质量；未合格保持默认关闭，完成后更新文档并交付main。
表面需求是补回准备材料、失败记录等步骤；本质需求是按用户请求覆盖可执行流程和关键条件，避免为了首段速度压掉动作。

## EARS
- REQ-601: WHEN用户要求操作流程/逐步说明，系统SHALL在首段给出主要操作规则与通用适用范围，并在后续答案按资料支持的顺序完整说明准备、执行、记录、异常处理及所问目的；每次发布的操作说明条件必须齐全；本次流程路径首次发布完整全文，后段不得推翻前段承诺，不能以用途概括代替具体动作。
- REQ-602: WHEN修复适用于分段生成，系统SHALL保持同一次模型生成、实际kept证据（仅排除已测极低相关异语候选并同步来源状态）、原2048预算/none/top_p=.8，流程选择温度0、其余生成.7、原引用/PII检查，比较、rewrite与非流程保持完整生成、终态和取消契约；不加入第二次模型核验。
- REQ-603: WHEN验证修复，系统SHALL把已看过的旧留出转为开发回归，进行多轮真实对照并冻结新的独立留出；区分首段、完整答案、检索未回答与截断，不按关键字命中冒充整题质量。
- REQ-604: WHEN默认启用资格尚未确认，系统SHALL保留分段默认false；只有新增留出无实质质量退步、调用不增且整体首段有收益后才决定默认；新发现不能静默放宽判据；默认资格只覆盖已验证的明确流程，不能把旧非流程分段一并启用。
