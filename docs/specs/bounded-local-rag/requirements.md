# Requirements

## Problem and Scope
表面问题是快速/深度模式正文等待过久；本质是小型本地混合模型在所有用途默认长思考，输出参数没有形成明确的本地调用契约，生成后又逐条重复调用同一模型。此前仅修关闭开关不足以交付。用户已确认自主修复、真实对照和完整验证后合并main。
范围：Qwen3.5:9b本地Ollama的RAG生成/控制调用策略、引用与完整结论提示、在线核验成本、必要回归与真实质量验证。外部provider、通用工具功能保持既有路径。不得把超时/空答案算质量通过。

## EARS
- REQ-001: WHEN 本地有依据RAG请求生成答案，THE SYSTEM SHALL 一次生成交付完整结论、证据引用、条件和缺失信息，不通过二次生成补写答案。
- REQ-002: WHILE 有界本地策略生效，THE SYSTEM SHALL 显式关闭此检索作答的隐式思考，使用引擎实际支持的输出预算及适当采样；深度模式保留既有检索/工具编排。
- REQ-003: WHEN 有界策略输出检查，THE SYSTEM SHALL 保留来源/PII/结构检查，在线语义评分未执行则为None/degraded，不能把未核验显示为通过。
- REQ-004: WHEN 配置未通过真实质量与耗时对照及冻结留出，THE SYSTEM SHALL 保持默认legacy；仅合格的本地策略可切为默认并继续保留legacy回滚。
- REQ-005: WHEN 完成实现，THE SYSTEM SHALL 将准确对应最终代码的单元、进程内E2E、真实多轮/留出及独立评审归档，CI通过后合并main。
