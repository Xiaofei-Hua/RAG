# Requirements

## Essential Need
在16GB单GPU、qwen3.5:9b及已合格Ollama格式回移版本上完成第3步调度和第4步分段发布，减少混合请求等待与完整正文前的空白时间；不能增加模型调用，也不能用未检查草稿冒充首段回答。用户2026-11-11明确授权完成实现、更新维护文档并推送GitHub；此前main合并授权继续适用。

## EARS
- REQ-301: WHEN同一本地模型并发调用，系统SHALL使用进程内统一有界队列和最多1个活动调用，覆盖同步/异步/流式入口、短控制与最终生成；取消和结束均释放占用。
- REQ-302: WHEN队列已满或等待超时，系统SHALL提供明确可重试的忙碌/不完整终态，不假装成功、不绕过队列再调用模型，不将不可用计为0分。
- REQ-303: WHEN调度启用，系统SHALL记录实际排队与服务时间，证明模式公平、取消和背压收益，不能把应用等待搬家称GPU吞吐提高。
- REQ-401: WHEN本地有界生成进入分段模式，系统SHALL在同一次生成中先提取简短证据，再输出首段完整结论（含会改变结论的全部条件）及后续解释；每个完整段经过编号/结构/PII等现有输出检查后才发布。
- REQ-402: WHEN后续生成截断/格式或检查失败，系统SHALL保留已检查正文并明确标为不完整，不重生、不撤换已交付内容；token拼接、done正文和保存正文一致，取消不写成功答案。
- REQ-403: WHEN任一新策略未通过真实质量与收益验证，系统SHALL保留独立回滚开关；不改变既有失败记录，不计拒答为有效首段。
- REQ-501: WHEN交付，系统SHALL完成独立并行设计与代码/质量评审、红绿单元+进程内E2E+相关Playwright、真实两轮对照和独立新留出，并更新README/API/部署/模块说明与CHANGELOG，分阶段合并main。
